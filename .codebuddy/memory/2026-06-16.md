## 中观热力图0615数据不显示 — ak_cache TTL 过长

**问题**: Dashboard 中观部分热力图和涨跌幅趋势图不显示0615数据。用户确认早上检验时数据存在。

**根因**: `industry_sw.py` 的 `get_daily_analysis` 使用 `ak_cache(ttl=86400)` 缓存24小时。同一参数组合在24小时内返回旧缓存，即使 akshare 已有新数据。前端 React Query staleTime=5min 但服务端24h才刷新。

**修复**: 
- `get_daily_analysis`: `ttl=86400` → `ttl=300`（5min，与前端 staleTime 对齐）
- `stock_zh_a_spot_em`（industry_sw.py + industry.py）: `ttl=86400` → `ttl=300`
- 需重启 MCP 服务 + 可选清理 `~/.cache/deep_fusion/` 磁盘缓存

**注意**: `CacheKey.init()` 用 key 做 singleton，已创建的 CacheKey 不更新 TTL。故改代码后必须重启服务才生效。

**趋势图数据源**: `industry_daily_query` 读本地 SQLite，不受 ak_cache 影响，但需要执行 `industry_daily_collect` 采集最新数据。

## wb_fred_adapter.py 代理架构重构

**问题**: FRED/WB（国际站点）需代理，akshare/NBS（国内站点）不需代理。全局设代理导致国内站受干扰。

**方案**: 双路代理尝试机制 `_flip_request()`
- Try 1: 用当前session配置（有proxy或无proxy）
- Try 2: 翻转 — 有proxy→无proxy重试，无proxy→用`INTERNATIONAL_PROXY`环境变量或默认`127.0.0.1:7897`重试
- `wb_fred_adapter.py` 从裸 `requests.get()` 改为 `safe_get()`（自带3次retry + UA轮换 + session proxy）

**关键**: Session proxy 在初始化时固化（来自 serve.py 的 env vars），akshare临时清 env 不会影响session。DB-first模式确保首次采集后永久缓存，后续无需网络请求。

**环境变量**: `INTERNATIONAL_PROXY` 可独立配置FRED/WB代理地址，默认 `http://127.0.0.1:7897`

**验证**: WB数据（中国GDP增长4.98%, 韩国债务/GDP 48.6%, 美国债务/GDP 118.0%）和FRED DB缓存（GS10 4.48%）均正常
