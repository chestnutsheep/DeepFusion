## 热力图数据滞后根因修复

### 问题
- 热力图(`industry_sw_daily`)数据来自 akshare `index_analysis_daily_sw` 接口（申万官方指数日报）
- 该接口更新慢，收盘后仍返回上一个交易日的数据（06-24收盘后仍返回06-22的数据）
- 而 `industry_daily_collect` 用的是同花顺接口，收盘后就有当天数据（DB已有06-24的90行）
- 导致热力图显示06-23，而DB实际有06-24数据

### 根因
- `get_daily_analysis()` 只从 akshare 拉数据，不读本地 DB
- akshare `index_analysis_daily_sw` 数据源更新滞后于同花顺数据源

### 修复
- `deep_fusion/data/sources/industry_sw.py` — `get_daily_analysis()` 增加 DB 补充逻辑
  - 先从 akshare 获取数据
  - 比较 akshare 最新日期 vs DB `meso_industry_daily` 最新日期
  - 若 DB 更新 → 从 DB 补充最新日期的所有行业行（LEFT JOIN classify 获取行业名）
  - DB 补充行的列名与 akshare 一致（指数代码/指数名称/发布日期/收盘指数/成交量/涨跌幅/换手率等）
  - DB 行的市盈率/市净率/均价/成交额占比/流通市值/股息率 为 NULL（前端 safeFloat 处理）
  - 日期格式统一：DB str → datetime.date，与 akshare 列类型一致
  - akshare 无数据时，全部从 DB 取
