### PMI/M2 数据缺失根因与修复
- **根因1**：`dispatch.py` 中 PMI/M2 的 `IndicatorDef.akshare_col` 列名错误
  - PMI: `制造业采购经理人指数` → 实际应为 `制造业-指数`
  - M2: `货币供应量同比增速` → 实际应为 `今值`
  - PPI: `工业生产者出厂价格指数` → 实际应为 `当月同比增长`
- **根因2**：PMI/M2 通过 `IndicatorDef(akshare_fn=...)` 获取，不走 `_nbs()` 的 DB-first 路径，akshare 调用失败时数据全为 None
- **修复**：
  - PMI/M2 改用 `_nbs("fetch_pmi", "pmi")` / `_nbs("fetch_m2_yoy", "m2_yoy")` 模式，走 DB-first + akshare 回退
  - `cycles.py` 新增 `_fetch_pmi()` / `_fetch_m2_yoy()` 函数，内部使用 `_fetch_with_priority()` (data_lake-first)
  - `_FN_MAP` 新增 `fetch_pmi` / `fetch_m2_yoy` 条目
  - `IndicatorDef.fetch()` 也加了 DB-first 逻辑（先查 cycle_data.db）
  - 手动运行脚本将 PMI(221行) + M2(330行) 写入 `cycle_data.db`
  - PPI 列名也已修正
