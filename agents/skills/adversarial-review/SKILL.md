# 对抗式辩论质量控制

用“分析师立论 + 挑战者驳论”的对抗式对话，从结构上消除单一 Agent 的“糊弄”倾向。

## 调用时机

- 同步自检：股票分析每个模块的分析产出草稿后触发。
- 异步审查：股票分析初稿完成后触发。

## 审查清单

对分析草稿逐项检查：

1. 反常是否被追问原因？还是用“市场错误定价”等模糊表述跳过？
2. 每个反常至少 2 个竞争性假设？只有 1 个 → 不合格。
3. 每个假设是否附带可检验预测？没有 → 不合格。
4. 是否使用“显然”“无疑”“必然”等词掩盖不确定性？
5. 推测是否标明了边界？推测被伪装成事实 → 不合格。
6. “无解”声明是否已穷尽可能的解释路径？过早放弃 → 不合格。

## 同步自检流程（单 Agent）

分析师在输出每段实质性分析内容前，自动以挑战者视角逐项检查：
→ 未通过项目 → 修正后重新检查
→ 全部通过 → 输出该段分析

## 异步审查流程（双 Agent）

1. 分析师产出完整草稿
2. 挑战者出具审查意见（违规项编号 + 引用原文 + 改进方向）
3. 分析师逐条回应：接受修正 / 数据反驳 / 声明边界
4. 修正后重新提交，直到 0 条违规或连续 2 轮仍有争议
5. 连续 2 轮仍有争议 → 保留争议点，显式标注“分析师与审查员未达成一致”，流程继续

## 死循环防护

连续 2 轮仍有违规 → 保留争议点往下走，不在当前阶段无限拉锯。
有些反常需要后续阶段的数据才能区分假设。
